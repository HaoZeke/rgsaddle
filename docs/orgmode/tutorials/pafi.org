#+title: PAFI: a free-energy profile and a rate
#+options: toc:nil num:nil author:nil

This tutorial takes a newcomer from a checkout to a PAFI free-energy profile and a rate, on an analytic surface, in Rust and in Python. Partial average force integration (PAFI) is Swinburne and Marinica, Phys. Rev. Lett. 120, 135503 (2018), doi:10.1103/PhysRevLett.120.135503: average the force projected onto a hyperplane normal to a reference path, at fixed arc length, and integrate that average along the path to the potential of mean force. =howto/oh-tst= covers the closely related optimal-hyperplane method, and =explanation/pafi-ohtst= compares the two and gives the equations this tutorial uses without deriving them.

#+begin_export rst
:cite:`swinburneUnsupervisedCalculation2018`
#+end_export

* What you need
A checkout of this repository and Rust 1.88 or newer. =python3= with no extra packages for the Python walkthrough below: it runs the compiled Rust example and reads its answer back, since PAFI has no Python session (=howto/python= covers what does).

* The surface
The surface is an analytic double well with a transverse mode whose stiffness varies along the reaction coordinate:

\[
V(x, y) = (x^2 - 1)^2 + \frac{1}{2} k(x) y^2, \qquad k(x) = 2.5 + 1.5 x.
\]

At fixed \(x\) the energy is smallest at \(y = 0\), where \(V = (x^2 - 1)^2\), the plain double well: minima at \(x = \mp 1\), both \(V = 0\), and a saddle at the origin, \(V = 1\). The valley floor is the straight line \(y = 0\), so a path along it has the path tangent and the hyperplane normal both along \(x\) everywhere, with no curvature correction to track. The transverse stiffness is \(k(-1) = 1\) at the reactant, \(k(0) = 2.5\) at the saddle, and \(k(+1) = 4\) at the product: stiffer toward the product, softer toward the reactant. Implementing =PointSurface= needs the energy and its Cartesian gradient:

#+INCLUDE: "../../../examples/pafi_tutorial.rs" src rust :lines "36-54"

Because \(k\) varies with \(x\) but not with \(y\), the transverse coordinate can be integrated out of the Boltzmann weight analytically at any fixed \(x\): it is a Gaussian of variance \(kT / k(x)\). That gives a closed form for the finite-temperature free energy along the path,

\[
F(x) = (x^2 - 1)^2 - \frac{1}{2} kT \ln\!\frac{2\pi kT}{k(x)},
\]

and so a closed form for the barrier this tutorial checks the sampled one against:

\[
\Delta F = F(0) - F(-1) = 1 + \frac{1}{2} kT \ln\frac{k(0)}{k(-1)}.
\]

#+INCLUDE: "../../../examples/pafi_tutorial.rs" src rust :lines "83-89"

This closed form exists only because the model is this simple. It is not part of PAFI and =rgsaddle::pafi= does not compute it; it is here only so the tutorial has a number to check the sampled barrier against without trusting the sampler to check itself.

* The path and the planes
=ArcPath::from_positions= takes a polyline through the given points and reports arc length, tangent and (since the polyline is piecewise straight) zero curvature on each segment. 21 points evenly spaced in \(x\) from \(-1\) to \(1\) at \(y = 0\) sit exactly on the valley floor:

* Sample the planes
=PafiConfig= is non-exhaustive; chain =with_*= setters from =default=:

#+INCLUDE: "../../../examples/pafi_tutorial.rs" src rust :lines "98-118"

=pafi_profile= takes 49 evenly spaced arc lengths, samples each of their hyperplanes by overdamped Langevin dynamics, and integrates the mean forces to the profile:

#+begin_src rust
let (profile, planes) = pafi_profile(&surface, &path, &arcs, &config.pafi)?;
#+end_src

It samples every plane in parallel on rayon's global pool; =howto/pafi-ohtst-parallel-sampling= times that. The planes are independent of each other: nothing here needs the center-of-mass projection (=with_fix_com(false)=, since there is only one moving coordinate to begin with) or extra sampling rounds (=with_retain(0)= keeps no configurations for a later restart; =howto/pafi-ohtst-restarting= covers both).

* Run it
#+begin_src console
$ cargo run --release --example pafi_tutorial
#+end_src

#+begin_example
zero-temperature barrier along the path: 0.999983 (potential barrier is 1)
PAFI barrier at kT = 0.1: 1.04478 +/- 0.00073
closed-form transverse-Gaussian barrier at this kT: 1.04581
reactant attempt frequency (unit mass): 0.45016
rate k = nu * exp(-barrier / kT): 1.306051e-5
largest plane autocorrelation time: 75.26 samples; smallest n_eff: 199.3
#+end_example

The sampled barrier, 1.04478 ± 0.00073, is 1.4 standard errors from the closed form, 1.04581: within the noise a Monte Carlo estimate carries. The worst plane's autocorrelation time is 75 samples and its effective sample count, =samples / (2 tau)=, is 199 out of 30000 recorded: comfortably above the handful that would make the block error untrustworthy (=howto/pafi-ohtst-checking-convergence= shows what that looks like when it is not comfortable).

* The rate
A rate needs a prefactor on top of the barrier. =attempt_frequency= turns a curvature into a frequency, \(\nu = \omega / 2\pi\) with \(\omega = \sqrt{\lambda / m}\); here \(\lambda\) is the curvature of the energy along the path tangent at the reactant, by a central finite difference, and the mass is 1 since the surface is already in mass-weighted-like units:

#+INCLUDE: "../../../examples/pafi_tutorial.rs" src rust :lines "68-81"

Arrhenius's law then gives the rate directly, with no unit conversion since both the barrier and \(kT\) are already in the surface's own energy unit (=crate::arrhenius= instead fixes eV and kelvin, and is the wrong call here):

#+begin_src rust
let rate = nu * (-profile.barrier / config.kt).exp();
#+end_src

Reactant attempt frequency 0.45016 and barrier 1.04478 at \(kT = 0.1\) give rate 1.306051e-5, printed above. =howto/oh-tst= computes the same kind of rate with an additional, independent dynamical correction, the transmission coefficient; =tutorials/oh-tst= compares the two numbers on this exact surface.

* From Python
PAFI is Rust-only: there is no =rgsaddle.pafi= Python module. The Python side of this tutorial drives the compiled Rust example instead, the same way a host language without its own PAFI binding would: write the run's settings to a small JSON file, invoke the binary with that file and an output path, and read the answer back.

#+INCLUDE: "../../../examples/pafi_tutorial.py" src python :lines "58-69"

#+begin_src console
$ cargo build --release --example pafi_tutorial
$ python3 examples/pafi_tutorial.py
#+end_src

#+begin_example
zero-temperature barrier along the path: 0.999983
PAFI barrier at kT = 0.1: 1.04478 +/- 0.00073
closed-form transverse-Gaussian barrier: 1.04581
reactant attempt frequency (unit mass): 0.45016
rate k = nu * exp(-barrier / kT): 1.306051e-05
measured barrier is 1.42 standard errors from the closed form
#+end_example

The two runs agree to the last printed digit: the JSON path sets exactly the same =PafiConfig= fields the Rust walkthrough does, down to the time step, so it draws the same chain from the same seed.
